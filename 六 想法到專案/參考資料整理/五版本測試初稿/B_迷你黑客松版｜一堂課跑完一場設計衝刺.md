> 計畫只有在時間壓力下，才會說真話。

先講一個你可能有過的經驗：

```text
第 1 週：我們來做一個超酷的 App！
第 2 週：先討論一下要用什麼技術。
第 3 週：還在討論功能要有哪些。
第 4 週：期中考，暫停。
第 8 週：那個 App……還要做嗎？
```

大部分的專案不是死在技術，是死在「一直在討論，從來沒做出一個能給人看的東西」。

Google 旗下的創投 GV（Google Ventures）為了解決這件事，發展出一套叫 **Design Sprint（設計衝刺）** 的方法：用 **五天**，從一個大問題走到一個被真實使用者測試過的原型。Jake Knapp 把它寫成了《Sprint》這本書，後來很多新創公司、Google 內部團隊都在用。

今天，我們要把五天壓縮成**一堂課**。

##### 出發前小提醒：今天幾乎不講理論。你會先「做」，最後才知道剛剛做的每一步，在軟體工程和專案管理裡叫什麼名字。

## 今天的任務

每一組要從一個主題出發，在下課前交出：

```text
✅ 一張使用者地圖
✅ 一個被選中的解法（以及一張「這次不做」清單）
✅ 一個別人能點、能操作的原型
✅ 至少 3 個人的測試紀錄
```

不需要能真的運作。**需要的是「能讓別人試用，並告訴你哪裡有問題」。**

下課時你會知道：

- 為什麼「先各自想、再一起選」比腦力激盪有效；
- 怎麼在吵不完的時候快速做決定；
- 原型要做到多真才夠；
- 怎麼觀察使用者，而不是聽他說客套話。

## 衝刺守則

開始之前，全組一起唸一遍：

| 守則 | 意思 |
| --- | --- |
| ⏰ **計時器說了算** | 時間到就停手，沒做完也停。這是在練習取捨，不是在練習完美 |
| 🤫 **一起，各自想** | 先安靜地各自寫、各自畫，再拿出來比。不要一開始就七嘴八舌 |
| ✏️ **醜沒關係** | 草圖不用會畫畫，原型不用好看，能看懂就好 |
| 👑 **Decider 拍板** | 吵不出結果時，交給決策者決定，然後往下走 |
| 📵 **手機收起來** | 除了做原型和查資料，不要滑手機 |

<details>
<summary>為什麼要「一起，各自想」？（打開看看）</summary>

傳統的腦力激盪（大家圍在一起喊點子）看起來很熱鬧，但常常是講話最大聲、最有自信的人主導，安靜的人的好點子就消失了。

《Sprint》書裡的核心原則之一就是 **Work alone together**：大家在同一個空間，但各自獨立完成想法，再用匿名、投票的方式挑選。這樣每個人的點子都有一樣的機會被看到。

</details>

## 第 0 關：組隊與角色卡

3–5 人一組。**混著組**：每組最好有人會用 AI 做網頁、有人擅長說話、有人擅長整理。

每個人抽（或選）一張角色卡：

| 角色 | 負責什麼 | 適合誰 |
| --- | --- | --- |
| 👑 **Decider（決策者）** | 投票後做最後決定；吵不出結果時拍板 | 願意負責、做決定不拖泥帶水的人 |
| ⏰ **Facilitator（主持＋計時）** | 帶流程、盯時間、提醒大家守則 | 會控場、敢打斷別人的人 |
| 🔨 **Maker（原型製作）** | 第 4 關負責把原型做出來 | 會用 Figma、會叫 AI 生網頁的人 |
| 🎤 **Interviewer（訪談員）** | 第 5 關負責帶使用者測試 | 會聊天、會觀察的人 |
| ✍️ **Writer（文字＋串接）** | 原型上的文字、確認每一頁接得起來 | 文字敏感、細心的人 |

人少就一人兼兩角。**Decider 和 Interviewer 很適合文組同學**，Maker 很適合會寫程式或很會用 AI 的同學。

> 小知識：Google 曾做過一個叫 Project Aristotle 的內部研究，想知道什麼樣的團隊表現最好。結果發現關鍵不是「誰在隊上」，而是「團隊怎麼合作」，其中一項就是**角色和目標清不清楚**。今天的角色卡就是在練這件事。

### 選主題

用自己組的點子也可以，沒有的話從下面挑一個：

| 主題卡 | 一句話 |
| --- | --- |
| 🧭 新生第一週 | 新生找不到教室、搞不清楚選課 |
| 🍱 三峽午餐 | 每天中午都在糾結吃什麼 |
| 📣 社團招生 | 社團擺攤，路過的人都不停下來 |
| 📚 期末考週 | 共筆散落各處，考前找不到 |
| 🚌 通勤 | 公車不知道什麼時候來，常常白等 |
| 🏠 宿舍生活 | 洗衣機永遠有人在用 |

接下來每一關，我們都用 **🧭「新生第一週」** 當示範。

## 第 1 關：Map 畫地圖

> 目標：把問題看清楚，選一個要攻擊的點。

### 1-1. 長期目標（一句話）

全組一起回答：

```text
如果這件事做成功了，一年後會是什麼樣子？
```

示範：「新生第一週，沒有人因為找不到教室而遲到。」

### 1-2. 衝刺問題（把擔心寫成問題）

把「這個點子可能會失敗的原因」，改寫成**可以用測試回答的問題**：

```text
擔心：新生可能根本不會打開我們的東西
→ 衝刺問題：新生在出發前，會想要先查教室位置嗎？

擔心：校園地圖太複雜，看不懂
→ 衝刺問題：新生能在 30 秒內看懂要走哪條路嗎？
```

寫 2–3 個就好。第 5 關測試的時候，我們就要回答這些問題。

### 1-3. 畫地圖

左邊寫「誰」，右邊寫「終點」，中間用 5–7 個步驟連起來：

```text
新生 → 收到課表 → 查教室在哪 → 出發 → 找到大樓 → 找到教室 → 準時坐下 ✅
```

### 1-4. HMW 便利貼（我們可以怎麼……？）

每個人**安靜地**寫便利貼，一張寫一個，格式是：

```text
我們可以怎麼（How Might We）＿＿＿＿＿＿？
```

示範：

```text
我們可以怎麼讓新生在出發前就知道要走多久？
我們可以怎麼讓大樓的入口更好找？
我們可以怎麼讓新生不用一直開地圖 App？
```

寫完後全部貼到牆上 → 把相似的放一起 → 每人 2 票（貼小圓點）→ 票最多的幾張貼到地圖上對應的步驟。

### 1-5. 選目標

Decider 決定：**我們今天只攻擊地圖上的哪一步？**

示範：「查教室在哪」這一步。

> 🎯 **第 1 關產出**：長期目標、2–3 個衝刺問題、一張地圖、一個被圈起來的攻擊點。

## 第 2 關：Sketch 各自畫

> 目標：每個人都產出一個完整的解法，不准討論。

### 2-1. 閃電展示（Lightning Demos）

每個人用手機查 1–2 個「別人怎麼解決類似問題」的例子（不一定要同類 App），每人花 1–2 分鐘給組員看。

示範：Google 地圖的步行導航、IKEA 地上的箭頭、捷運站的出口編號。

### 2-2. 四步草圖

| 步驟 | 做什麼 | 建議時間 |
| --- | --- | --- |
| ① Notes 筆記 | 安靜地看一遍牆上的地圖、HMW、閃電展示，抄下有用的 | 5 分鐘 |
| ② Ideas 點子 | 隨便寫、隨便畫，把想到的都倒出來，圈出最好的 | 5 分鐘 |
| ③ Crazy 8s 瘋狂八格 | 一張紙折成 8 格，**每格 1 分鐘**，畫出同一個點子的 8 種變化 | 8 分鐘 |
| ④ Solution Sketch 解法草圖 | 選最好的一個，畫成 **3 格分鏡**，下面寫說明，取一個吸睛的標題 | 10–15 分鐘 |

Crazy 8s 的重點不是畫得好，是**逼你跳過第一個想到的點子**。第一個點子通常是最普通的，第 5、6 個才會開始有趣。

解法草圖的規則：

- **不寫名字**（匿名，等一下投票才公平）；
- 文字比圖重要，看不懂的圖旁邊一定要寫字；
- 要能**自己講得通**：別人不用聽你解釋，看圖就懂。

> 🎯 **第 2 關產出**：每個人一張 3 格的解法草圖。

## 第 3 關：Decide 做決定

> 目標：不吵架，快速選出要做的那一個。

這一關是《Sprint》書裡被稱為「便利貼決策」的流程，**整個過程幾乎不討論**：

| 步驟 | 做什麼 |
| --- | --- |
| 🖼 **美術館** | 把所有解法草圖貼在牆上排成一排 |
| 🔴 **熱點圖** | 每個人安靜地看，在喜歡的**部分**貼 1–3 個小點（可以貼很多張） |
| 🗣 **快速評論** | 每張草圖 2–3 分鐘：主持人講解這張圖、大家講亮點和疑問，**作者最後才能說話** |
| 🗳 **草根投票** | 每人一張大點，投給最想做的那一個（不具約束力） |
| 👑 **超級票** | Decider 有 3 票，投給要做成原型的那張 |

Decider 不一定要選票最多的。這就是決策者存在的意義：**聽完大家的意見，然後負責做決定**。

### 3-1. 「之後也許」清單

沒被選上的點子不要丟，寫在一張紙上，標題叫「之後也許」。

> 💡 這張清單，就是專案管理裡說的「**範疇管理**」。你不是不要那些點子，是**這次不做**。

### 3-2. 畫分鏡

把選中的解法畫成 **6–8 格**的使用者故事，從使用者「打開它之前在幹嘛」開始，到「完成目標」結束：

```text
① 新生在宿舍看課表 → ② 掃描課表上的 QR code → ③ 看到教室在哪棟、幾樓
→ ④ 看到「從宿舍走過去約 8 分鐘」→ ⑤ 按「帶我去」→ ⑥ 跟著箭頭走到大樓
→ ⑦ 大樓入口照片 → ⑧ 準時坐下 ✅
```

分鏡上**沒出現的東西，第 4 關就不做**。

> 🎯 **第 3 關產出**：一張被選中的解法、一張「之後也許」清單、一張 6–8 格分鏡。

## 第 4 關：Prototype 只做門面

> 目標：做出一個「看起來像真的」的東西，讓測試者有真實的反應。

### 4-1. 原型 = 電影布景

想像電影裡的西部小鎮：街道、酒館、警長辦公室看起來都很真，但走到後面會發現只有一片木板撐著。

原型就是這樣。**只做使用者會看到的那一面**，後面全是假的也沒關係。

《Sprint》書裡把這叫做「**金髮女孩品質**（Goldilocks quality）」：不能太粗糙（測試者會覺得是假的，不認真回答），也不要太精緻（浪費時間，而且你會捨不得改）。**剛好夠真就好。**

### 4-2. 選工具

| 工具 | 難度 | 適合 | 特色 |
| --- | --- | --- | --- |
| 📄 紙本原型 | 🟢 | 所有人 | 一張紙一個畫面，測試時你當「電腦」換紙 |
| 📊 Google 簡報 + 超連結 | 🟢 | 所有人 | 每頁一個畫面，按鈕連到下一頁 |
| 📝 Google 表單 | 🟢 | 流程是填資料的點子 | 真的能填，結果會進試算表 |
| 🎨 Figma | 🟡 | 會一點設計的人 | 可以做出很像 App 的點擊原型 |
| 🤖 AI 生成單頁 HTML | 🟡 | 會用 AI 的人 | 看起來最像真的網頁 |
| 💻 真的寫程式 | 🔵 | 技術強的人 | 只做分鏡那條路，其他按鈕都是假的 |

- AI 做原型的參考 prompt：

```text
請根據下面的分鏡，做一個可以點擊的單頁 HTML 原型。
［貼上 6–8 格分鏡］
規則：
- 只做分鏡上的畫面和按鈕，其他按鈕可以存在但點了沒反應；
- 資料全部寫死，不需要資料庫、不需要登入；
- 手機尺寸，整體風格簡單乾淨；
- 全部寫在一個 index.html 檔案裡。
```

### 4-3. 分工

| 角色 | 這關做什麼 |
| --- | --- |
| Maker | 做畫面 |
| Writer | 寫畫面上的所有文字（按鈕、標題、提示）——**真實的文字**，不要寫「這裡放文字」 |
| Interviewer | 準備第 5 關的訪談腳本 |
| Facilitator | 盯時間，提醒大家只做分鏡上的東西 |
| Decider | 遇到「這裡要不要加……」時拍板（答案通常是：不要） |

做完後**全組試跑一次**：從頭到尾點一遍，確定沒有斷掉的地方。

> 🎯 **第 4 關產出**：一個可以從分鏡第 1 格點到最後一格的原型。

## 第 5 關：Test 給真人測

> 目標：觀察別人怎麼用，回答你的衝刺問題。

### 5-1. 怎麼測？

跟隔壁組交換：你們測他們的，他們測你們的。每組至少找 **3 個人**測（能到 5 個更好）。

為什麼是 5 個？《Sprint》的週五固定訪談 5 位使用者；尼爾森諾曼集團（Nielsen Norman Group）的使用者經驗研究也指出，同一類使用者測到第 5 個左右，大部分嚴重問題就會重複出現了，與其一次測很多人，不如測 5 個、改一改、再測一次。

### 5-2. 五幕訪談腳本

Interviewer 照這個流程走：

| 幕 | 做什麼 | 說什麼（範例） |
| --- | --- | --- |
| ① 歡迎 | 讓對方放鬆 | 「我們在測試這個東西，不是在測試你，用不好是我們的錯。」 |
| ② 背景 | 問他的真實經驗 | 「你開學第一週有找不到教室過嗎？那時候怎麼辦？」 |
| ③ 介紹 | 交代情境，不解釋功能 | 「假設你剛收到課表，想知道第一堂課在哪。」 |
| ④ 任務 | 讓他自己操作，**請他邊做邊講** | 「你現在會想按哪裡？你覺得這個畫面在說什麼？」 |
| ⑤ 回顧 | 問整體感受 | 「如果明天真的要用，你會用嗎？哪裡最卡？」 |

### 5-3. 訪談的三個禁忌

```text
❌ 不要解釋：「喔那個按鈕是要……」→ 他看不懂，就是你做得不清楚
❌ 不要辯護：「其實我們本來想做……」→ 你不會跟著產品一起送給每個使用者
❌ 不要相信客套話：「很棒啊！」→ 看他做了什麼，不要聽他說了什麼
```

### 5-4. 觀察員記錄

其他組員在旁邊（或後面）安靜觀察，用三種顏色便利貼記錄：

| 顏色 | 記什麼 |
| --- | --- |
| 🟩 綠色 | 順利的地方、正面反應 |
| 🟥 紅色 | 卡住、困惑、點錯的地方 |
| 🟨 黃色 | 測試者說的原話（直接抄） |

### 5-5. 計分板

測完之後，把便利貼依測試者排好，回到第 1 關的衝刺問題，一題一題看：

| 衝刺問題 | 測試者 1 | 測試者 2 | 測試者 3 | 結論 |
| --- | --- | --- | --- | --- |
| 新生出發前會想先查教室嗎？ | ✅ | ✅ | ❌ | 大部分會 |
| 能在 30 秒內看懂路線嗎？ | ❌ | ❌ | ✅ | **要改** |

如果 3 個人裡有 2 個人卡在同一個地方，那就不是測試者的問題，是設計的問題。

> 🎯 **第 5 關產出**：觀察便利貼＋計分板。

## 第 6 關：Retro 剛剛到底發生了什麼

恭喜你，剛剛跑完了一場設計衝刺。
現在來揭曉：**你剛剛做的每一件事，在真實世界都有名字。**

| 剛剛做的事 | 軟體工程／專案管理的名字 | 真實世界用在哪 |
| --- | --- | --- |
| 計時器說了算 | **Timebox（時間盒）** | Scrum 的 Sprint、黑客松、每週例會 |
| 長期目標＋衝刺問題 | **目標設定＋風險識別** | 專案啟動會議、提案書 |
| 畫地圖 | **使用者旅程（User Journey）** | UX 設計、需求分析 |
| HMW 便利貼 | **問題重構（Problem Reframing）** | 設計思考、黑客松發想 |
| 各自畫草圖再投票 | **發散 → 收斂** | 所有創意與決策流程 |
| Decider 拍板 | **決策權（如 Scrum 的 Product Owner）** | 任何團隊都需要有人負責做決定 |
| 「之後也許」清單 | **範疇管理（Scope Management）** | 決定 MVP 要做到哪裡 |
| 只做門面的原型 | **原型（Prototype）／MVP** | 新創驗證點子、提案 demo |
| 5 個人測試 | **易用性測試（Usability Testing）** | 產品上線前的驗證 |
| 角色卡 | **團隊分工與角色定義** | 任何團隊專案 |

### 6-1. 全組回顧（Retro）

圍成一圈，每人回答三題：

```text
1. 今天哪一關卡最久？為什麼？
2. 我們砍掉了什麼？砍得對嗎？
3. 如果再跑一次，我會改哪一件事？
```

### 6-2. 從衝刺到專案：下一步三選一

看著計分板，Decider 做最後一個決定：

| 測試結果 | 下一步 |
| --- | --- |
| 衝刺問題大多是 ✅ | **開工**：把分鏡每一格變成一個待辦（GitHub Issue），開始做真的版本 |
| 有幾題 ❌，但方向對 | **修改再測**：改原型，再找 3–5 個人測一次 |
| 大部分 ❌，大家根本不需要 | **換方向**：恭喜！你只花一堂課就發現了，而不是花一學期 |

> 第三種結果**不是失敗**。用一堂課發現一個點子行不通，比寫了三個月程式才發現，便宜太多了。

### 一個人也能衝刺

自己做個人作品的時候，可以跑一個「單人迷你版」：

```text
1. 自己當 Decider：寫下長期目標和 2 個衝刺問題
2. 畫地圖，選一個攻擊點
3. Crazy 8s 畫 8 種解法，選一個畫成分鏡
4. 用 AI 生一個單頁原型（只做分鏡那條路）
5. 找 3 個朋友測，觀察他們卡在哪
6. 決定：開工／修改／換方向
```

一個週末就能跑完。比你一個人關在房間寫一個月程式，再發現沒人看得懂，好太多了。

## 大總結啦

> **「與其花一學期討論，不如花一堂課做出來給人測。」**

### 一：設計衝刺的五關

$$\text{Map} \rightarrow \text{Sketch} \rightarrow \text{Decide} \rightarrow \text{Prototype} \rightarrow \text{Test}$$

* **Map（地圖）**：長期目標、衝刺問題、使用者地圖，選一個攻擊點。
* **Sketch（草圖）**：一起、各自想。Crazy 8s 逼你跳過第一個爛點子。
* **Decide（決定）**：美術館、熱點圖、投票、Decider 拍板。沒選上的進「之後也許」。
* **Prototype（原型）**：只做門面，剛好夠真就好。
* **Test（測試）**：觀察 5 個人，看他做什麼，不要聽他說什麼。

### 二：今天偷偷學到的專案管理

* **Timebox**：時間到就停，逼你做取捨。
* **範疇管理**：「之後也許」清單就是你的範疇邊界。
* **決策權**：團隊需要一個人負責拍板，不然會一直吵。
* **驗證**：原型的目的是學習，不是完美。

### 三：衝刺守則，帶走一輩子

* 計時器說了算。
* 一起，各自想。
* 醜沒關係。
* 吵不贏，就交給 Decider。

### 給文組同學的話

今天的五關裡，最難的不是做原型，是**問對問題、觀察別人、做出決定**。
Decider 和 Interviewer 這兩個角色，在業界分別接近產品經理和使用者研究員，都是文組背景的人大放異彩的職位。你可能沒寫一行程式，但今天這個原型長什麼樣子，是你決定的。

### 給電資組同學的話

你今天可能是 Maker，十分鐘就用 AI 生出了一個很像樣的原型。但你應該也發現了：**做得出來和做對的東西是兩回事**。測試的時候，你最得意的那個功能可能根本沒人點。把這個體感帶回去，下次寫程式之前，先找 3 個人看一下你的分鏡，會省下你很多個晚上。
