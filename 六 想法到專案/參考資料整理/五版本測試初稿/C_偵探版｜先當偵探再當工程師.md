> 你想做的東西，不一定是別人需要的東西。

先問一個殘忍的問題：

**你上一個做到一半、或做完的作品，現在還有人在用嗎？包括你自己？**

很多人的作品，不是死在技術，而是做完才發現：

```text
「啊……大家好像都用 LINE 群組就解決了。」
「我覺得很需要，但我朋友都說『還好欸』。」
「做完我自己也沒在用。」
```

有了 AI 之後，這件事變得更危險：寫程式變得太容易了，容易到你可以在一個晚上做出一個**沒有人需要的東西**。

今天我們要學的，是偵探的工作：在動手寫程式之前，先找證據。

##### 出發前小提醒：今天大部分時間不會寫程式。但你會學到一套方法，讓你之後寫的每一行程式都更有價值。這套方法也直接適用於黑客松提案、商業競賽和創業。

## 今天的任務

下課時，你會帶走一張「**偵探報告**」：

```text
📌 我的點子：一句話
📌 我的假設清單，以及最危險的那一個
📌 一份訪談筆記（至少訪問 1 個人，課後補到 3 個）
📌 一張實驗卡：用什麼方法、多久、怎樣算成功
📌 結論：繼續／調整／換方向
```

而且你能：

- 分辨「好問題」和「會騙你的問題」；
- 把一個點子拆成可以被證明錯誤的假設；
- 不寫一行程式，就測試一個點子有沒有人要。

今天的貫穿範例是：**「北大二手教科書交換平台」**。
這是一個每學期都有人想做的點子。我們來看看，它到底需不需要被做出來。

## 0. 寫 code 是最貴的驗證方式

想知道一個點子有沒有人要，有很多種方法。它們的成本差很多：

| 驗證方式 | 花多少時間 | 能學到什麼 | 可信度 |
| --- | --- | --- | --- |
| 自己覺得很需要 | 0 | 你自己的想法 | ⭐ |
| 問朋友「你覺得這個點子好嗎？」 | 5 分鐘 | 客套話 | ⭐ |
| 用正確的方法訪談 5 個人 | 2–3 小時 | 他們真實的經驗和痛點 | ⭐⭐⭐ |
| 做一個預告頁，看多少人留 email | 半天 | 有多少人有興趣 | ⭐⭐⭐ |
| 自己當人肉系統，手動服務幾個人 | 幾天 | 他們會不會真的用、會不會回來 | ⭐⭐⭐⭐ |
| **寫一個完整的程式** | **幾週到幾個月** | 全部 | ⭐⭐⭐⭐⭐ |

寫程式能學到最多，但也最貴。
如果你的點子在第三列就被推翻了，你就省下了幾週的時間。

> **寫 code 是最貴的驗證方式。** 能用便宜的方法知道答案，就不要用貴的。

<details>
<summary>這套想法從哪裡來？精實創業（打開看看）</summary>

這種「先驗證、再開發」的思考方式，主要來自 **精實創業（Lean Startup）**。核心是一個循環：

```text
Build（做一個東西）→ Measure（測量反應）→ Learn（學到什麼）→ 再做
```

精實創業的重點是：**每一次循環，都要盡量便宜、盡量快**。所以它推崇 MVP（最小可行產品）：用最小的東西去測試你的假設。

後來有人覺得「MVP」這個詞被濫用了，很多人還是花好幾個月做一個「最小」產品。2016 年，Rik Higham 寫了一篇文章提出 **RAT（Riskiest Assumption Test，最危險假設測試）**：不要先問「最小的產品長什麼樣」，先問「**我最可能錯在哪裡？**」，然後用最便宜的方法測那一件事。

今天的課，就是 RAT 的思考方式。

</details>

## 1. 想法是「注意到」的，不是「想出來」的

很多人坐在電腦前想：「我要做什麼 App 才會紅？」然後想出一堆聽起來很酷、但沒人需要的東西。

矽谷創業加速器 Y Combinator 的創辦人 Paul Graham 寫過一篇很有名的文章〈How to Get Startup Ideas〉。他的建議很簡單：**好點子不是想出來的，是注意到的。** 最好的點子，通常來自你自己真的遇過的問題。

### 1.1 痛點日記

接下來一週，每次你遇到下面這些情況，就記下來：

```text
😤 我又在抱怨……
🔁 這件事我每週都要重複做一次，好煩……
🤷 為什麼沒有人做一個……
📝 我用了一個很爛的土法煉鋼方法在解決……
```

最後一種最有價值。**如果你已經用 Excel、LINE 記事本、截圖相簿在硬撐一件事，那代表這個問題是真的。**

### 1.2 篩選你的點子

把痛點日記裡的點子拿來打分數：

| 點子 | 多常發生？ | 多痛？ | 現在怎麼解決？ | 我自己會用嗎？ |
| --- | --- | --- | --- | --- |
| 二手教科書交換 | 每學期初一次 | 中（課本很貴） | 臉書社團、學長姐直接給 | 可能會 |
| 社團器材借用登記 | 每週 | 中（常找不到誰借走） | LINE 群組問 | 會 |
| 午餐決定器 | 每天 | 低 | 隨便選 | 會 |

沒有標準答案，但如果某一欄你寫不出來，就是你該去調查的地方。

<details>
<summary>麻煩的事，反而是機會（打開看看）</summary>

Paul Graham 還有另一篇文章叫〈Schlep Blindness〉。Schlep 是「又累又煩的苦差事」的意思。

他的觀察是：人的大腦會自動忽略那些「做起來很麻煩」的點子，連想都不去想。但正因為大家都避開，那些麻煩的問題反而沒人解決，是很好的機會。

所以當你想到一個點子，第一個反應是「這好麻煩喔」的時候，先別急著跳過。

</details>

## 2. 把想法拆成假設，找出最危險的那一個

每一個點子，其實都是一串「**我相信……**」疊起來的。
只要其中一個是錯的，整個點子就會垮掉。

### 2.1 一頁畫布：先把點子攤開

在拆假設之前，先用五個格子把點子攤開。這是從 Ash Maurya 的 **Lean Canvas（精實畫布）** 簡化來的：

| 格子 | 問自己 | 二手教科書的例子 |
| --- | --- | --- |
| 誰（客群） | 誰有這個問題？誰會最先用？ | 北大大一、大二學生，尤其是必修課很多的科系 |
| 問題 | 他們遇到什麼麻煩？（寫前三個） | 課本很貴；不知道哪裡有人賣二手；面交約時間很麻煩 |
| 現在怎麼解決 | 沒有你的東西，他們現在怎麼辦？ | 臉書二手社團、直系學長姐、影印 |
| 解法 | 你打算怎麼解決？ | 一個依課程分類的二手書平台 |
| 為什麼選你 | 為什麼他們要用你的，而不是現在的方法？ | 依課號搜尋，一秒找到 |

注意第三格「**現在怎麼解決**」。這一格是最多人忘記填的，也是最致命的。
**你的對手從來不是別的 App，是使用者「現在的習慣」。**

### 2.2 把每一格變成假設

用這個句型，把畫布改寫成假設：

```text
我相信［誰］有［什麼問題］，
他們現在用［什麼方法］解決，但不滿意，
而且他們願意［付出什麼：時間／錢／改變習慣］來換一個更好的方法。
```

二手教科書的假設清單：

```text
A. 我相信北大學生覺得課本很貴，想買二手。
B. 我相信他們現在找二手書很困難。
C. 我相信他們不滿意臉書社團的方式。
D. 我相信有足夠多的學長姐願意把舊書上架。
E. 我相信買賣雙方願意面交。
```

### 2.3 找出最危險的假設

把每個假設放到這張圖上：

```text
              如果錯了，點子會死
                     ↑
      ┌──────────────┼──────────────┐
      │  ⚠️ 最危險    │  重要，但     │
      │  先測這裡！   │  已經有證據   │
      │              │              │
  沒證據 ────────────┼────────────── 有證據
      │              │              │
      │  不重要      │  不重要       │
      │  先不管      │  而且有證據   │
      └──────────────┼──────────────┘
                     ↓
              錯了也還好
```

左上角那一格，就是你今天要測的。

二手教科書的分析：

| 假設 | 錯了會死嗎？ | 有證據嗎？ | 位置 |
| --- | --- | --- | --- |
| A. 覺得課本很貴 | 會 | 有（大家都在抱怨） | 右上 |
| B. 找二手書很困難 | 會 | **沒有** | ⚠️ 左上 |
| C. 不滿意臉書社團 | 會 | **沒有** | ⚠️ 左上 |
| D. 學長姐願意上架 | 會 | **沒有** | ⚠️ 左上 |
| E. 願意面交 | 不太會（可以改寄送） | 有 | 右下 |

有三個都在左上角！這時候選**最可能錯的那一個**。
以這個例子來說，D 最危險：**平台最怕的是有人要買、沒人要賣**。沒有書，買家來一次就不會再來了。

> 🎯 **偵探守則**：你最想做的功能，通常不是你最該先驗證的東西。

### 🧪 換你做

1. 用五格畫布攤開你的點子。
2. 寫出至少 4 條假設。
3. 放進四象限，圈出最危險的那一條。

## 3. Mom Test：怎麼問才不會被騙

找到最危險的假設之後，最直覺的做法是去問人。
但你問的方式，很可能會讓你得到完全錯誤的答案。

### 3.1 為什麼叫 Mom Test？

Rob Fitzpatrick 寫了一本書叫《The Mom Test》。書名的意思是：**就算你問的是你媽，你也要能得到真實的答案。**

你媽愛你。你問她「我想做一個二手書平台，妳覺得好不好？」，她一定說好。
你朋友也是。大部分人都是。**沒有人想當面潑你冷水。**

```text
❌ 你：我想做一個二手教科書平台，你覺得怎麼樣？
   朋友：哇，好像不錯欸！我應該會用！
   你：（覺得點子被驗證了，回家寫了一個月程式）
   朋友：（從來沒用過）
```

問題不是朋友說謊，是你問了一個**只能得到客套話**的問題。

### 3.2 三條規則

| 規則 | 意思 |
| --- | --- |
| 1. **聊他的生活，不要聊你的點子** | 一提到你的點子，對方就會開始「評價」，然後客氣 |
| 2. **問過去發生的具體事情，不要問未來的意見** | 人對過去的事記得很準，對未來的事很會亂猜 |
| 3. **少說，多聽** | 你講越多，學到越少 |

### 3.3 三種「會騙你的資料」

訪談中聽到這些，要自動打折：

| 壞資料 | 長什麼樣子 | 怎麼處理 |
| --- | --- | --- |
| 💐 **稱讚** | 「好酷喔！」「好棒的點子！」 | 不算數。稱讚對對方來說不用付出任何代價 |
| ☁️ **空話** | 「我**通常**會……」「我**應該**會……」「我**可能**會……」 | 拉回具體的過去：「上一次是什麼時候？」 |
| 💡 **對方給的點子** | 「你應該加一個聊天功能！」 | 不要直接記下來，往下挖：「為什麼你會想要這個？」 |

### 3.4 爛問題 → 好問題

| ❌ 爛問題（會得到客套話） | ✅ 好問題（會得到真實經驗） |
| --- | --- |
| 你覺得二手書平台是好點子嗎？ | 你這學期的課本是怎麼買的？ |
| 你會用這種平台嗎？ | 你上一次買二手書是什麼時候？從哪裡買的？ |
| 你會想把舊書賣掉嗎？ | 你上學期的課本現在在哪裡？ |
| 你覺得臉書社團好用嗎？ | 你上次在臉書社團買東西，過程是怎樣？哪裡最麻煩？ |
| 如果有這個功能你會付錢嗎？ | 你為了解決這件事，花過多少錢或時間？ |
| （沒問） | 我還有什麼應該問、但沒問到的嗎？ |
| （沒問） | 你覺得我還應該去問誰？ |

最後兩題是萬用好問題，每次訪談結束前都可以問。

### 3.5 往下挖：功能要求背後的真正需求

```text
受訪者：「你應該做一個可以看書況照片的功能。」
❌ 你：好！記下來！（新增功能：上傳照片）
✅ 你：為什麼照片對你很重要？
受訪者：「因為上次買到一本整本都畫滿螢光筆的。」
✅ 你：那次後來怎麼處理？
受訪者：「就算了，懶得退。」
```

你挖出來的不是「要上傳照片」，是「**怕買到劃記太多的書**」。這可能有更簡單的解法（例如賣家勾選「無劃記／少量／大量」），不一定需要照片功能。

### 3.6 承諾：說「好」不算，付出才算

訪談結束時，可以試著請對方付出一點點東西：

| 承諾 | 例子 |
| --- | --- |
| ⏰ 時間 | 「下週我做好一個簡單版，可以約你 10 分鐘試用嗎？」 |
| 🤝 名聲 | 「你可以把我介紹給你們班上也在找書的同學嗎？」 |
| 💰 錢或東西 | 「你願意先把一本舊書放到我們的清單上嗎？」 |

對方願意付出越多，這個需求越真實。
如果他說「好啊好啊」但什麼都不願意付出，那可能只是客氣。

> **對方拒絕也是好資料。** 真正的失敗是你從頭到尾都沒開口問。

### 3.7 訪談小技巧

- **輕鬆聊天**，不要像在做問卷調查。說「我在研究大家怎麼買課本」，不要說「我在做一個 App」。
- **兩個人一起去**：一個人問，一個人記。
- **記原話**，不要只記你的解讀。
- **問到聽不到新東西為止**。通常 3–5 個人，同一類人的回答就會開始重複。如果 10 個人講 10 種完全不同的話，代表你的「誰」太廣了，要縮小。
- **尊重受訪者**：說明用途、不追問隱私、不記錄不必要的個人資料。

### 🧪 換你訪談

兩人一組，互相訪談 **10 分鐘**（第三個人當觀察員，記下訪談者有沒有犯規）。

觀察員檢查表：

| 犯規項目 | 次數 |
| --- | --- |
| 訪談者提到自己的點子 |  |
| 問了未來式的問題（「你會……嗎？」） |  |
| 訪談者講話比受訪者多 |  |
| 聽到稱讚就很開心，沒有往下挖 |  |

## 4. 設計實驗：先寫好怎樣算成功

訪談能告訴你**問題是不是真的**。但「他們會不會真的用你的解法」，要靠實驗。

### 4.1 為什麼要事先寫成功標準？

因為人很會在事後自圓其說：

```text
做之前：「如果有很多人填表單，就代表有需求！」
做之後：「只有 3 個人填……但這 3 個人都很認真！所以有需求！」
```

事先寫清楚，就沒辦法耍賴了。

### 4.2 實驗卡

這個格式改編自 Strategyzer 的 **Test Card**：

```text
┌─────────────────────────────────────────┐
│ 🧪 實驗卡                               │
├─────────────────────────────────────────┤
│ 1. 我們相信：                            │
│    （你最危險的假設）                     │
│                                         │
│ 2. 為了驗證，我們會：                     │
│    （用什麼方法，見下一節）                │
│                                         │
│ 3. 我們會觀察：                          │
│    （數什麼？看什麼行為？）                │
│                                         │
│ 4. 如果＿＿＿＿，我們就是對的：            │
│    （具體的數字和期限）                   │
└─────────────────────────────────────────┘
```

二手教科書的範例：

```text
1. 我們相信：學長姐願意把上學期的課本拿出來賣。
2. 為了驗證，我們會：在系上 LINE 群組發一則「舊書收集」貼文，附 Google 表單。
3. 我們會觀察：一週內，有多少人填表單登記要賣的書。
4. 如果一週內有 15 本以上的書被登記，我們就是對的。
```

### 4.3 實驗結束後：學習卡

```text
1. 我們原本相信：＿＿＿＿
2. 實際觀察到：＿＿＿＿
3. 我們學到：＿＿＿＿
4. 所以我們決定：繼續／調整／換方向
```

| 結果 | 決定 | 意思 |
| --- | --- | --- |
| 達到標準 | ✅ **繼續** | 測下一個最危險的假設，或開始做 |
| 有反應但沒達標 | 🔄 **調整** | 改變「誰」、改變「解法」，再測一次 |
| 幾乎沒反應 | 🔀 **換方向** | 這個點子先放下，回去看你的痛點日記 |

## 5. 不寫 code 的 MVP

這是今天最有趣的部分：**你可以在不寫一行程式的情況下，測試一個「產品」。**

### 5.1 四種方法

| 方法 | 怎麼做 | 使用者知道是人工嗎？ | 經典例子 |
| --- | --- | --- | --- |
| 🙋 **人肉服務**（Concierge） | 你親自手動提供服務 | 知道 | 你親自幫人配對買賣 |
| 🧙 **綠野仙蹤**（Wizard of Oz） | 前台看起來像產品，後台是你在手動處理 | 不知道 | Zappos |
| 🚪 **預告頁**（Fake Door／Smoke Test） | 做一個介紹頁，看多少人點「我要用」 | 點了才知道還沒上線 | 很多新創上線前都會做 |
| 🎬 **影片 Demo** | 做一支影片展示「如果有這個產品」 | 知道 | Dropbox |

<details>
<summary>經典例子的故事（打開看看）</summary>

**Zappos（網路鞋店）**：創辦人想知道「大家願不願意在網路上買鞋」。他沒有先建倉庫、進貨，而是去附近的鞋店拍照、放上網站。有人下單，他就去店裡用原價買下來，再寄給客人。每一筆都賠錢，但他用很便宜的方式證明了「有人願意在網路上買鞋」。

**Dropbox（雲端硬碟）**：雲端同步的技術很難做，要花很久。創辦人 Drew Houston 先做了一支幾分鐘的影片，展示「如果有這個產品，會長什麼樣子」，附上等待名單，發到科技社群。等待名單暴增，證明大家真的想要，才放心投入開發。

兩個例子都在回答同一個問題：**在花大錢、大時間之前，先確定有人要。**

### 5.2 二手教科書可以怎麼測？

| 要測的假設 | 方法 | 具體做法 | 工具 |
| --- | --- | --- | --- |
| D. 學長姐願意賣 | 🙋 人肉服務 | 在系群發「舊書收集」表單 | Google 表單 |
| C. 不滿意臉書社團 | 🚪 預告頁 | 做一頁「依課號找二手書」的介紹，放「通知我上線」按鈕 | Google Sites、Carrd |
| B. 找書很困難 | 🧙 綠野仙蹤 | 做一個「輸入課號，我們幫你找」的表單，後台你自己去社團翻 | Google 表單 + 你自己 |
| 會不會真的完成交易 | 🙋 人肉服務 | 你親自當媒合人，用 LINE 把買家和賣家拉在一起 | LINE、試算表 |

最後一種最真實。如果你親自媒合了 10 筆交易，你會學到一大堆你坐在電腦前永遠想不到的事：

```text
- 原來大家最在意的是「書上有沒有劃記」
- 原來很多人只想買「上一屆的版本」
- 原來面交最大的問題是「約不到時間」
- 原來大部分交易都集中在開學前兩週
```

這些都會變成你之後寫程式時的**規格**。

### 5.3 小提醒

- **預告頁要誠實**：使用者點了「我要用」之後，要清楚告訴他「我們還在準備中，留下 email 會第一個通知你」，不要讓人覺得被騙。
- **點「通知我」只代表好奇，不代表會用**。如果可以，讓對方多付出一點（例如填寫他要賣的書名），訊號會更準。
- **人數不用多**。你要的是學習，不是漂亮的數字。認真跟 5 個填表單的人聊一聊，比數到 100 個 email 有用。

### 🧪 換你設計

幫你最危險的假設，選一種不寫 code 的方法，填完實驗卡。
**限制：這個實驗要能在 48 小時內開始執行。**

## 6. 這時候，才開始寫 code

通過驗證之後，你終於可以開始寫程式了。
但這時候的你，跟一開始的你完全不一樣：

| 一開始的你 | 現在的你 |
| --- | --- |
| 「我覺得大家需要一個二手書平台」 | 「我知道學長姐願意賣，而且買家最在意劃記程度」 |
| 功能清單有 20 項 | 只做被證明有需要的 3 項 |
| 不知道要先做什麼 | 從人肉服務裡最痛的那一步開始自動化 |

### 6.1 從人肉服務到程式

最好的起點，是**你手動做最累的那一步**。

```text
你手動做的事                       → 第一個要寫的程式
每天整理表單、配對買家賣家         → 依課號自動列出可買的書
一直被問「書況怎樣」               → 賣家上架時勾選劃記程度
```

- 參考用 prompt：

```text
我在做一個［點子］。以下是我驗證過的事實：
- ［訪談學到的事 1］
- ［實驗結果］
- ［使用者最在意的事］

我目前手動在做的流程是：［描述］。
請先不要寫程式。幫我規劃一個「只自動化最累那一步」的最小版本：
1. 需要哪些功能（最多 3 個）；
2. 哪些事情可以繼續手動做；
3. 用什麼工具最簡單（不一定要寫程式，試算表也算）。
```

注意第 2、3 點：**不是每件事都要寫程式**。有時候一個 Google 試算表加上表單，就能撐很久。

### 6.2 如果你只是想做一個練功的作品？

不是每個作品都要有「市場」。如果你只是想做一個給自己用、或練習技術的作品，偵探的問題可以改成：

```text
❓ 我自己真的會用嗎？（用一週看看）
❓ 我身邊有沒有一個人也會用？（找他用一週看看）
❓ 做完之後，我能拿它跟別人講出一個好故事嗎？（作品集、面試）
```

**自己就是第一個使用者，也是一種驗證。** 只是你要對自己誠實。

## 7. 大挑戰時間

選一個等級挑戰：

- **Level 1**：完成五格畫布和假設清單，圈出最危險的假設。
- **Level 2**：用 Mom Test 訪談至少 1 個人（課堂上），寫下 3 句受訪者的原話。
- **Level 3**：填完實驗卡，並在課後 48 小時內真的開始執行。
- **Level 4（🔵 進階）**：做一個預告頁（Google Sites／Carrd／自己寫的單頁 HTML），加上表單，一週後帶著數據回來分享，填完學習卡。

## 大總結啦

> **「在寫第一行程式之前，先找到第一個證據。」**

### 一：偵探的四步

$$\text{Notice} \rightarrow \text{Assume} \rightarrow \text{Interview} \rightarrow \text{Experiment}$$

* **Notice（注意）**：好點子來自你注意到的痛點，不是坐著想出來的。
* **Assume（假設）**：每個點子都是一串假設，找出「錯了就死、又沒證據」的那一個。
* **Interview（訪談）**：Mom Test 三規則，聊他的生活、問過去、少說多聽。
* **Experiment（實驗）**：先寫好成功標準，用最便宜的方法測。

### 二：Mom Test 防騙指南

* 稱讚不算數。
* 「我通常／應該／可能會」都是空話，拉回「上一次是什麼時候」。
* 功能要求要往下挖：「為什麼你想要這個？」
* 說「好」不算，願意付出時間、名聲或錢才算。

### 三：不寫 code 的 MVP

* 🙋 人肉服務：你親自做。
* 🧙 綠野仙蹤：前台像產品，後台是你。
* 🚪 預告頁：看多少人想要，記得誠實。
* 🎬 影片 Demo：展示「如果有的話」。

### 給文組同學的話

今天這堂課，你們應該是主場。
訪談、觀察、找出別人沒說出口的需求、把模糊的東西整理成假設，這些都是社會科學和商管訓練出來的能力。很多工程師可以三天寫出一個平台，卻花三個月才發現沒人要。**你們能做的，是讓那三個月不要被浪費。** 黑客松和商業競賽的評審，最常問的就是「你怎麼知道有人需要？」，今天的偵探報告就是你的答案。

### 給電資組同學的話

今天可能是你最坐不住的一堂課，因為幾乎沒寫程式。
但想想看：你之前做過的 side project，有幾個是因為「技術做不出來」而放棄的？又有幾個是因為「做完沒人用（包括自己）」而放棄的？技術能力讓你**能**做出任何東西，偵探能力讓你知道**該**做什麼。兩個都有的人，非常非常少。
