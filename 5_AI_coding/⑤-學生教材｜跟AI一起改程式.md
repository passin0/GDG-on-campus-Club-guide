# 第 ⑤ 堂｜Vibe Coding → AI Coding：跟 AI 一起改程式

> 目標不是背語法。  
> 目標是：AI 寫出東西後，你知道怎麼問、怎麼改、怎麼確認它真的能用。

## 今天的任務

你會拿到一個小工具（待辦清單、計算器或小測驗），替它加上一個小規則。

完成時，你要能留下：

- 我理解這段程式的方式
- 我發現的問題與證據
- 我的修改要求
- 修改後的測試結果

---

## 1. 先看故事，不先背符號

每一段程式都可以先問三件事：

```text
輸入：它拿到什麼？
  ↓
處理：它拿這些東西做了什麼？
  ↓
輸出：最後出現什麼結果？
```

### 小例子：折扣計算器

```js
function calculatePrice(price, discount) {
  const finalPrice = price * (1 - discount)
  return finalPrice
}
```

| 程式裡的東西 | 用人話說 |
| --- | --- |
| `price`、`discount` | 輸入：原價和折扣 |
| `price * (1 - discount)` | 處理：算出折扣後的價格 |
| `return finalPrice` | 輸出：把結果交回去 |

### 練習 ①：幫你的程式翻譯

| 它的輸入是什麼？ | 它中間做了什麼？ | 最後輸出／改變什麼？ |
| --- | --- | --- |
|  |  |  |

> 看不懂一行時，先問 AI：「這一行改變了什麼？」不要急著叫它整份重寫。

## 2. Function：一個有名字的小幫手

```js
function addTask(taskName) {
  // 把一件待辦事項加進清單
}
```

把 Function 想成有名字的小幫手：它拿到需要的資料，專心完成一件事，再把結果交出去或改變畫面。

讀一個 Function，只要先回答：

1. 它叫什麼？猜得出它的任務嗎？
2. 它需要什麼資料？
3. 做完後，結果去哪裡？

### 練習 ②：找到一位小幫手

| Function 名稱 | 它需要什麼？ | 它完成什麼？ | 我還不確定什麼？ |
| --- | --- | --- | --- |
|  |  |  |  |

## 3. Debug：給 AI 能重現的證據

AI 不會讀心。這句話太模糊：

```text
按鈕壞掉了，幫我修。
```

把它換成任何人都能重現的描述：

```text
我在做［工具名稱］。
我輸入／操作［具體內容］後，原本預期［預期結果］，
但實際發生［實際結果或錯誤訊息］。
請先推測最可能的原因，告訴我如何測試；
確認後只修改必要部分，並解釋改了什麼。
```

## 4. 改之前先預測，改之後一定測試

請選一個小改動，或提出自己的版本：

- 空白的待辦事項不能新增
- 金額不能是負數
- 答對時顯示鼓勵訊息
- 清單上顯示目前項目數
